# Dirt Trail

A 2D arcade motocross game. Three tracks, two bikes, and a trick system that only
pays out if you actually ride away from the landing.

Built in Unity 6 (6000.0.59f2) with URP 2D, Cinemachine 3 and the Input System.

## Where this came from

This started as a small snowboarding project. It worked, but it was fairly basic:
one track, a surface effector dragging the player along, flips worth a flat 100
points each, and no menus at all. Over a few days I rebuilt almost all of it.

What stayed is the core idea of a single Rigidbody2D pushed around by forces and
torque, because that arcade feel is the good part. Nearly everything else is new:

* Physics that runs in `FixedUpdate` and knows what slope it is standing on
* Two raycasts (one per axle) instead of a single overlap check
* Landings graded by the angle you hit the ground at
* Flips, doubles, airtime bonuses, combos, and points you can lose
* Three tracks with their own shape, palette and feel
* Menus, a garage, a track select, pause, and a results screen
* Comic book style burst art for every trick and crash
* Sound, synthesised at startup rather than shipped as audio files

## Playing it

Open `Assets/Scenes/MainMenu.unity` and press play.

| Action   | Keyboard          | Gamepad          |
|----------|-------------------|------------------|
| Throttle | `W` or `Up`       | Right trigger, A |
| Brake    | `S` or `Down`     | Left trigger, B  |
| Lean     | `A` `D` or arrows | Left stick X     |
| Nitro    | `Shift` or `Space`| X                |
| Pause    | `Esc`             | Start            |
| Restart  | `R`               | Y                |

Lean left to lift the nose (that is a backflip), lean right to drop it (a
frontflip). Nitro is banked as a charge when you pick it up rather than fired
automatically, so choosing when to burn it is up to you.

Menus work with the mouse as well as the keyboard. Hovering a row moves the same
highlight the arrow keys use, so the two never fight over what is selected.

## The three tracks

Each one differs in four ways at once, not just colour: the shape of the ground,
the silhouette behind it, the palette, and what grows on it.

| Track | Length | Jumps | What it is like |
|---|---|---|---|
| **Ridge Run** | 1046 units | 9 | Warm desert buttes. Rollers, kickers, whoops, a bowl, a staircase and a tabletop. The one to learn on. |
| **Gravel Pit** | 652 units | 6 | An overcast quarry with cut benches. Short steep faces and drops rather than jumps, a tighter camera, and the only track where braking really matters. |
| **Dust Devil** | 1266 units | 3 | Dusk on the open flats. Long fast ground between three enormous jumps, all of which hang for over two seconds. |

Best score and best time are saved separately for each track.

## Scoring

Points build up while you are in the air and are only banked once you land. Crash
and you lose the lot, which is the whole reason to either commit to a flip or
shut it down early.

| | |
|---|---|
| First rotation | 100 |
| Each further rotation in the same air | 100 more each, so a double is 300 |
| Airtime past 1.1 seconds | 25 per half second, capped at 300 |
| Clean landing | x1.25 |
| Perfect landing (within 12 degrees of the slope) | x1.5 |
| Combo | +0.25 per trick in a row, capped at x3, lapses after 7 seconds |
| Reaching the finish | 500 |

## How the art works

There are no drawn assets in this repo. Every sprite in `Assets/Sprites` is
generated by the Python in `Tools/artgen`, which only needs Pillow. That covers
the bike and rider, the terrain, the parallax backdrops, the props, the pickups,
the particle textures, the UI plates and the comic bursts.

```bash
python Tools/artgen/gen_bike.py       # bike, rider and wheels, two liveries
python Tools/artgen/gen_terrain.py    # sprite shape edge and fill, per theme
python Tools/artgen/gen_parallax.py   # four backdrop layers, per theme
python Tools/artgen/gen_props.py      # rocks, plants, pickups, FX, UI plates
python Tools/artgen/gen_shouts.py     # the comic burst sprites
```

Scenes, prefabs and ScriptableObjects are generated too:

```bash
python Tools/artgen/build_assets.py   # bike and pickup configs, tracks, skins
python Tools/artgen/build_prefab.py   # the bike, pickups, checkpoints
python Tools/artgen/build_track.py    # all three track scenes
python Tools/artgen/build_menus.py    # menu, garage and track select
```

The generators are deterministic. Every GUID is derived from the asset path, so
regenerating art never breaks a reference in a scene or a prefab.

`Tools/artgen/track_profile.py` holds all three track layouts and can fly every
takeoff at a range of entry speeds to report how far and how long it flies. Run it
on its own to print the table. Jump distances were sized from that rather than by
eye.

## Layout

```
Assets/Scripts/
  Core/         enums, layers, save data, scene routes, settings
  Bike/         controller, ground sensor, visuals, dust, config
  Tricks/       rotation and landing turned into a score
  Pickups/      typed pickups
  Track/        run state, checkpoints, finish, track configs
  CameraRig/    look ahead, air framing, zoom, impulses
  Environment/  parallax
  UI/           skin, builders, HUD, menus, comic bursts
  Audio/        procedural engine and impact synthesis
Tools/artgen/   the art and scene pipeline
```

Physics runs in `FixedUpdate` and presentation in `LateUpdate`. Tuning lives in
ScriptableObjects under `Assets/Resources` rather than being scattered through
the code.

## Checking it still works

There are two batch mode checks in `Assets/Editor`. The first opens every scene
and reports missing scripts, unresolved sprites and empty Resources:

```bash
Unity.exe -batchmode -nographics -quit -projectPath . -executeMethod DirtTrail.EditorTools.BuildValidator.Validate
```

The second actually enters play mode and rides all three tracks on a pinned
throttle with an auto level, then reports whether each one was finished:

```bash
Unity.exe -batchmode -nographics -projectPath . -executeMethod DirtTrail.EditorTools.PlaytestRunner.Run
```

## Notes

There is no recorded audio. `ProceduralSfx` synthesises the engine loop, the
landing, the wipeout, the pickup and the trick chime at startup from a few dozen
lines of DSP. Swapping in real clips is a one line change per sound.

UI text uses the LiberationSans font that ships with TextMesh Pro. The lettering
inside the comic bursts is DejaVu Sans Bold, which is open licensed and baked
into the PNGs, so there is no font dependency at runtime.
